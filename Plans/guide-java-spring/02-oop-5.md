# Records

**Level: Beginner | Phase 2 | Priority: MUST | Since: Java 16 (preview 14), record patterns Java 21**

> **30-second interview answer:** A record is a concise, final class for immutable data. From `record Point(int x, int y) {}` the compiler generates private final fields, a canonical constructor, accessor methods `x()` and `y()`, and `equals`, `hashCode` and `toString` based on all components. You can add validation in a compact constructor, plus static and instance methods. Records are ideal for DTOs, API requests and responses, query projections and map keys, but not for JPA entities, which must be mutable and proxyable.

## 1. Concept in Simple Words
### Analogy
A printed shipping label.

| Shipping label | Java record |
|---|---|
| Fixed boxes: name, address, weight | Components declared in the header |
| Printed once, cannot be edited | Fields are final, no setters |
| Two labels with identical text count as the same | `equals` and `hashCode` from all components |
| Reading a box | Accessor `name()` |
| The printer rejects a negative weight | Validation in the compact constructor |

### What it is
```text
record Point(int x, int y) { }
```
generates:
- `private final int x; private final int y;`
- canonical constructor `Point(int x, int y)`
- accessors `int x()` and `int y()` (no `get` prefix)
- `equals`, `hashCode`, `toString` using all components → `Point[x=1, y=2]`

Rules:
- Records are implicitly `final` and extend `java.lang.Record`; they cannot extend other classes but can implement interfaces.
- No extra instance fields beyond components; static fields are allowed.
- **Compact constructor:** `Point { if (x < 0) throw ...; }` runs before the fields are assigned; you can also normalize parameters (`name = name.trim();`).
- Nested records are implicitly static. Local records (inside methods) are allowed.

### Why it exists
Plain data classes needed 40+ lines of boilerplate (fields, constructor, getters, equals, hashCode, toString), often generated by Lombok. Records make the intent ("this is just data") explicit, correct and short.

## 2. How It Works
```text
record Money(long cents, String currency) {
    Money {                                   // compact canonical constructor
        Objects.requireNonNull(currency);
        if (cents < 0) throw new IllegalArgumentException();
        currency = currency.toUpperCase();    // reassigns the PARAMETER
    }                                         // then: this.cents = cents; this.currency = currency;
}
```

**Shallow immutability:** the fields are final, but if a component is a mutable object (`List`), its contents can change. Copy in the compact constructor: `items = List.copyOf(items);`.

**Record patterns (Java 21)** let you deconstruct records directly:
```text
if (obj instanceof Point(int x, int y)) { use x and y }
switch (shape) { case Circle(double r) -> ...; case Square(double s) -> ...; }
```

**Where records fit in a Spring Boot app**
| Use | Record? |
|---|---|
| Request and response DTOs (Jackson supports records) | Yes |
| `@ConfigurationProperties` classes | Yes |
| Spring Data projections (`List<OrderSummary>`) | Yes |
| Events published with `ApplicationEventPublisher` | Yes |
| JPA `@Entity` | No: entities need a no-arg constructor, mutability and non-final classes for proxies |

## 3. Code Example
### Code
```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Objects;

public class RecordsDemo {

    record Point(int x, int y) {
        static final Point ORIGIN = new Point(0, 0);       // static field allowed

        double distanceTo(Point other) {                   // instance method
            return Math.hypot(x - other.x, y - other.y);
        }

        Point withX(int newX) { return new Point(newX, y); } // "wither": new copy
    }

    record Money(long cents, String currency) {
        Money {                                            // compact constructor
            Objects.requireNonNull(currency, "currency");
            if (cents < 0) throw new IllegalArgumentException("negative amount");
            currency = currency.toUpperCase();             // normalize
        }

        Money(long cents) { this(cents, "USD"); }          // extra constructor must delegate

        Money plus(Money other) {
            if (!currency.equals(other.currency)) throw new IllegalArgumentException("currency mismatch");
            return new Money(cents + other.cents, currency);
        }
    }

    record Order(String id, List<String> items) {
        Order {
            items = List.copyOf(items);                    // defensive copy: deep enough for Strings
        }
    }

    sealed interface Shape permits Circle, Square { }
    record Circle(double radius) implements Shape { }
    record Square(double side) implements Shape { }

    static double area(Shape s) {
        return switch (s) {                                // record patterns (Java 21)
            case Circle(double r) -> Math.PI * r * r;
            case Square(double side) -> side * side;
        };
    }

    public static void main(String[] args) {
        Point a = new Point(3, 4);
        System.out.println(a + " x=" + a.x() + " distance=" + a.distanceTo(Point.ORIGIN));
        System.out.println("withX: " + a.withX(10) + ", original unchanged: " + a);
        System.out.println("equals: " + a.equals(new Point(3, 4)));

        Map<Point, String> grid = new HashMap<>();         // records are great map keys
        grid.put(new Point(1, 1), "tree");
        System.out.println("lookup: " + grid.get(new Point(1, 1)));

        Money m = new Money(1250, "eur");
        System.out.println(m + " plus " + m.plus(new Money(50, "EUR")));
        System.out.println(new Money(99));
        try {
            new Money(-1, "USD");
        } catch (IllegalArgumentException e) {
            System.out.println("rejected: " + e.getMessage());
        }

        List<String> source = new ArrayList<>(List.of("pen"));
        Order order = new Order("O-1", source);
        source.add("hack");                                // does not affect the record
        System.out.println(order);

        System.out.printf("areas: %.2f %.2f%n", area(new Circle(1)), area(new Square(2)));

        Object obj = new Point(7, 8);
        if (obj instanceof Point(int x, int y)) {          // deconstruct in one step
            System.out.println("deconstructed x+y=" + (x + y));
        }
    }
}
```

### Walkthrough
- `Point` gets fields, constructor, accessors and the three `Object` methods automatically. It adds a static constant, an instance method and a "wither" that returns a modified copy.
- `Money`'s compact constructor validates and normalizes the currency before the fields are assigned. The extra constructor `Money(long)` must delegate to the canonical one with `this(...)`.
- `Order` copies the list with `List.copyOf`, so later changes to `source` do not leak in.
- The sealed `Shape` with record implementations allows an exhaustive switch with record patterns, no `default` needed.
- `obj instanceof Point(int x, int y)` checks the type and extracts components in one step.

### Output
```text
Point[x=3, y=4] x=3 distance=5.0
withX: Point[x=10, y=4], original unchanged: Point[x=3, y=4]
equals: true
lookup: tree
Money[cents=1250, currency=EUR] plus Money[cents=1300, currency=EUR]
Money[cents=99, currency=USD]
rejected: negative amount
Order[id=O-1, items=[pen]]
areas: 3.14 4.00
deconstructed x+y=15
```

### Compare
| Record | Lombok `@Value` | Ordinary class |
|---|---|---|
| Language feature, no library | Annotation processor | Hand-written |
| Accessors `x()` | Getters `getX()` | Whatever you write |
| Always final, all fields final | Final by default | Anything |
| Cannot extend classes | Can extend | Can extend |
| Supports record patterns | No | No |

## 4. Interview Questions
**Basic**
1. **What is a record?**
   A final class for immutable data whose fields, constructor, accessors, equals, hashCode and toString are generated from its components.
2. **What is a compact constructor?**
   A canonical constructor without a parameter list, used for validation and normalization; field assignment happens automatically after it runs.
3. **Can a record extend another class or have extra fields?**
   No to both: it already extends `Record` and may only have the component fields as instance fields. It can implement interfaces and have static fields.

**Follow-up**
4. **Are records fully immutable?**
   Shallowly. Fields are final, but mutable components like lists can change unless you copy them in the compact constructor.
5. **Why can't you use a record as a JPA entity?**
   JPA needs a no-arg constructor, mutable state for dirty checking, and non-final classes for lazy-loading proxies; records are final and immutable.
6. **How does Jackson handle records?**
   Since Jackson 2.12 it deserializes using the canonical constructor and serializes using the accessors, so records work as Spring MVC request and response bodies.

**Tricky / scenario**
7. **What does `record Point(int x, int y)`'s accessor look like: `getX()` or `x()`?**
   `x()`. Some older libraries that expect JavaBean getters will not see record components.
8. **You want a record with a derived field `total` from `price * quantity`. How?**
   Do not add a field; add a method `double total() { return price * quantity; }`. Extra instance fields are not allowed.

**What the interviewer is really testing:** knowledge of modern Java and where records fit in a Spring application.

## 5. Pitfalls & Best Practices
### Common mistakes
| Mistake | What goes wrong | Fix |
|---|---|---|
| Passing a mutable list into a record | Record content changes later | `List.copyOf` in the compact constructor |
| Using records as JPA entities | Hibernate errors | Use records for DTOs and projections only |
| Arrays as components | `equals` compares array references | Use `List`, or override equals and hashCode |
| Assigning `this.x = x` inside a compact constructor | Compile error | Reassign the parameter only |

### Best practices
- Use records for DTOs, events, configuration properties, value objects and map keys.
- Validate in the compact constructor so invalid records cannot exist.
- Provide "wither" methods for modified copies.

### Compare with
| Type | Use for |
|---|---|
| record | Data with a fixed set of fields |
| enum | A fixed set of instances |
| class | Behaviour-rich objects with mutable state (entities, services) |

Write `record CreateOrderRequest(String customerEmail, List<OrderLine> lines)` and `record OrderLine(String sku, int quantity)`. Validate: email not blank and contains `@`; lines not empty; quantity between 1 and 100. Normalize the email to lower case. Add a method `int totalQuantity()`.

<details><summary>Solution</summary>

```java
import java.util.List;

public class OrderRequestDemo {
    record OrderLine(String sku, int quantity) {
        OrderLine {
            if (sku == null || sku.isBlank()) throw new IllegalArgumentException("sku required");
            if (quantity < 1 || quantity > 100) throw new IllegalArgumentException("quantity 1..100");
        }
    }

    record CreateOrderRequest(String customerEmail, List<OrderLine> lines) {
        CreateOrderRequest {
            if (customerEmail == null || !customerEmail.contains("@"))
                throw new IllegalArgumentException("valid email required");
            if (lines == null || lines.isEmpty()) throw new IllegalArgumentException("at least one line");
            customerEmail = customerEmail.trim().toLowerCase();
            lines = List.copyOf(lines);
        }

        int totalQuantity() {
            int sum = 0;
            for (OrderLine l : lines) sum += l.quantity();
            return sum;
        }
    }

    public static void main(String[] args) {
        var req = new CreateOrderRequest(" Ann@Shop.com ",
                List.of(new OrderLine("BOOK-1", 2), new OrderLine("PEN-9", 5)));
        System.out.println(req.customerEmail() + " " + req.totalQuantity()); // ann@shop.com 7
        try {
            new OrderLine("X", 0);
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());                             // quantity 1..100
        }
    }
}
```

</details>

# Immutable Class Design

**Level: Beginner | Phase 2 | Priority: MUST | Since: design principle (String immutable since Java 1.0)**

> **30-second interview answer:** An immutable object cannot change after construction. The recipe: make the class final, all fields private and final, no setters, initialize everything in the constructor, make defensive copies of mutable inputs, and never return references to internal mutable objects. Immutable objects are thread-safe without locks, safe as map keys, easy to cache and reason about. "Changes" return new objects, like `String.toUpperCase()` or `LocalDate.plusDays()`.

## 1. Concept in Simple Words
### Analogy
A printed photograph versus a whiteboard.

| Photo vs whiteboard | Java |
|---|---|
| A printed photo never changes | Immutable object |
| To "edit" it you print a new photo | Methods return new objects |
| Anyone can look at it at once without fights | Thread safety without locks |
| A whiteboard can be erased by anyone in the room | Mutable shared object: race conditions |
| A laminated photo of a whiteboard drawing | Defensive copy of a mutable input |

### What it is
**The five-step recipe**
1. Declare the class `final` (or use a private constructor with static factories) so no subclass can add mutable state.
2. Make all fields `private final`.
3. Provide no setters or other mutating methods.
4. **Defensive copy in:** copy mutable arguments (lists, arrays, `Date`) in the constructor.
5. **Defensive copy out:** never return internal mutable objects; return copies or unmodifiable views.

JDK examples: `String`, wrapper classes, `BigDecimal`, `BigInteger`, `LocalDate` and the whole `java.time` API, `List.of`, records with immutable components.

### Why it exists
Most concurrency bugs and many "who changed this?" bugs come from shared mutable state. Immutable objects remove that whole class of bugs.

## 2. How It Works
**Why defensive copies matter:**
```text
List<String> tags = new ArrayList<>(List.of("new"));
Product p = new Product("Pen", tags);     // constructor stores the SAME list (no copy)

tags ---------> ["new"] <--------- p.tags
tags.add("sale")       -> p now has ["new", "sale"]: p changed without calling p!

With List.copyOf(tags) in the constructor:
tags ---------> ["new", "sale"]
p.tags -------> ["new"]   (separate, unmodifiable)
```

**Copy before validating (TOCTOU):** copy the input first, then validate the copy. Otherwise another thread could change the argument between your check and your copy.

**"Modification" returns a new instance:**
```text
LocalDate d1 = LocalDate.of(2026, 1, 1);
LocalDate d2 = d1.plusDays(1);   // d1 is still 2026-01-01
```

**Thread safety:** final fields correctly assigned in the constructor are visible to all threads without synchronization (Java Memory Model guarantee), as long as `this` does not escape the constructor.

**Cost:** every change creates a new object. Usually cheap (young-generation GC handles short-lived objects well). For heavy step-by-step building, use a mutable builder (`StringBuilder`) and produce the immutable result at the end.

## 3. Code Example
### Code
```java
import java.util.ArrayList;
import java.util.Date;
import java.util.List;
import java.time.LocalDate;

public class ImmutableDemo {

    // Broken "immutable" class: final fields but leaks
    static final class LeakyEvent {
        private final String name;
        private final Date date;            // java.util.Date is mutable
        private final List<String> guests;

        LeakyEvent(String name, Date date, List<String> guests) {
            this.name = name;
            this.date = date;               // no copy in
            this.guests = guests;           // no copy in
        }
        Date getDate() { return date; }     // no copy out
        List<String> getGuests() { return guests; }
    }

    // Correct immutable class
    static final class Event {                          // 1. final class
        private final String name;                      // 2. private final fields
        private final LocalDate date;                   // LocalDate is already immutable
        private final List<String> guests;

        Event(String name, LocalDate date, List<String> guests) {
            List<String> copy = List.copyOf(guests);    // 4. copy in (before validating)
            if (copy.size() > 100) throw new IllegalArgumentException("too many guests");
            this.name = name;
            this.date = date;
            this.guests = copy;
        }

        // 3. no setters; "changes" return new objects
        Event withGuest(String guest) {
            List<String> next = new ArrayList<>(guests);
            next.add(guest);
            return new Event(name, date, next);
        }

        Event postponeDays(int days) { return new Event(name, date.plusDays(days), guests); }

        List<String> getGuests() { return guests; }     // 5. already unmodifiable
        LocalDate getDate() { return date; }

        @Override public String toString() { return name + " on " + date + " " + guests; }
    }

    public static void main(String[] args) {
        // Leaky version: state changes behind the object's back
        List<String> list = new ArrayList<>(List.of("Ann"));
        Date when = new Date(0);
        LeakyEvent leaky = new LeakyEvent("Party", when, list);
        list.add("Intruder");
        leaky.getDate().setTime(999_999_999_999L);
        System.out.println("leaky guests: " + leaky.getGuests());
        System.out.println("leaky date changed: " + (leaky.getDate().getTime() != 0));

        // Correct version
        List<String> source = new ArrayList<>(List.of("Ann"));
        Event e1 = new Event("Launch", LocalDate.of(2026, 12, 1), source);
        source.add("Intruder");                            // no effect
        Event e2 = e1.withGuest("Bob").postponeDays(7);     // new objects
        System.out.println("e1: " + e1);
        System.out.println("e2: " + e2);
        try {
            e1.getGuests().add("Hacker");
        } catch (UnsupportedOperationException ex) {
            System.out.println("cannot modify guests from outside");
        }

        // JDK immutables behave the same way
        String s = "hello";
        String upper = s.toUpperCase();
        System.out.println(s + " -> " + upper + " (original unchanged)");
    }
}
```

### Walkthrough
- `LeakyEvent` has final fields, yet its state changes: the caller's list and the mutable `Date` are shared in and out.
- `Event` follows all five steps. `List.copyOf` makes an unmodifiable copy (validated after copying), and `LocalDate` is already immutable, so no copy is needed.
- `withGuest` and `postponeDays` return new `Event` objects; `e1` never changes.
- `getGuests` can return the field directly because it is already unmodifiable.
- `String.toUpperCase` shows the same idea in the JDK.

### Output
```text
leaky guests: [Ann, Intruder]
leaky date changed: true
e1: Launch on 2026-12-01 [Ann]
e2: Launch on 2026-12-08 [Ann, Bob]
cannot modify guests from outside
hello -> HELLO (original unchanged)
```

### Compare
| Immutable | Mutable |
|---|---|
| Thread-safe without locks | Needs synchronization when shared |
| Safe as map keys and in sets | Can corrupt hash collections |
| Easy to cache and share | Must copy before sharing |
| New object per change | Changes in place, fewer allocations |

## 4. Interview Questions
**Basic**
1. **How do you create an immutable class?**
   Final class, private final fields, no setters, all state set in the constructor, defensive copies of mutable inputs, and no internal mutable references returned.
2. **Why are immutable objects thread-safe?**
   Their state never changes after construction, so threads can share them without races, and final fields are safely published by the memory model.
3. **Name immutable classes in the JDK.**
   `String`, `Integer` and other wrappers, `BigDecimal`, `LocalDate`, `LocalDateTime`, `Duration`, `List.of` collections.

**Follow-up**
4. **Why must the class be final?**
   A subclass could add mutable fields or override methods to expose changing state, breaking the guarantee for code that holds a parent reference.
5. **What is a defensive copy and when do you need it?**
   A copy of a mutable object made when it enters (constructor) or leaves (getter) your class, so outside code cannot change your internal state.
6. **Why copy before validating?**
   To avoid time-of-check to time-of-use bugs: another thread could change the original argument between your check and your copy.

**Tricky / scenario**
7. **Is a class with only final fields immutable?**
   Not necessarily: a final field can reference a mutable object (a list, a `Date`) that is shared or returned.
8. **Immutable objects create lots of garbage. Is that a performance problem?**
   Usually not: short-lived objects are cheap for generational GCs. For heavy building, use a mutable builder internally, then create the immutable result.

**What the interviewer is really testing:** a precise checklist and the reasons behind each step, including the hidden leaks.

## 5. Pitfalls & Best Practices
### Common mistakes
| Mistake | What goes wrong | Fix |
|---|---|---|
| Storing the caller's list directly | Caller changes your state | `List.copyOf` in the constructor |
| Returning an internal array | Caller edits your elements | Return `array.clone()` or a List |
| Using `java.util.Date` fields | Mutable | Use `java.time` types |
| Class not final | Subclass breaks immutability | `final` or private constructor |

### Best practices
- Use records for simple immutable data, adding copies for mutable components.
- Use `java.time`, `List.of`, `Map.of`, `Set.of` and `BigDecimal`.
- Make value objects (Money, Email, Address) immutable; keep entities mutable but encapsulated.

### Compare with
| Tool | Gives |
|---|---|
| `final` keyword | A fixed reference only |
| `Collections.unmodifiableList` | A read-only view of a list that may still change underneath |
| `List.copyOf` | An independent, unmodifiable copy |
| Immutable class | A whole object that can never change |

Make this class immutable without changing its public constructor signature:

```java
public class Team {
    public String name;
    public String[] members;
    public Team(String name, String[] members) { this.name = name; this.members = members; }
    public String[] getMembers() { return members; }
}
```

<details><summary>Solution</summary>

```java
import java.util.Arrays;

public final class Team {
    private final String name;
    private final String[] members;

    public Team(String name, String[] members) {
        this.name = name;
        this.members = members.clone();      // copy in: Strings are immutable, so a shallow clone is enough
    }

    public String getName() { return name; }
    public String[] getMembers() { return members.clone(); }   // copy out

    public Team withMember(String m) {
        String[] next = Arrays.copyOf(members, members.length + 1);
        next[members.length] = m;
        return new Team(name, next);
    }

    public static void main(String[] args) {
        String[] arr = {"Ann", "Bob"};
        Team t = new Team("Core", arr);
        arr[0] = "Mallory";                       // no effect
        t.getMembers()[1] = "Eve";                // no effect
        System.out.println(Arrays.toString(t.getMembers()));                  // [Ann, Bob]
        System.out.println(Arrays.toString(t.withMember("Cy").getMembers())); // [Ann, Bob, Cy]
    }
}
```
</details>

# Coding drill: OOP design

## 1. Predict the output: overriding vs hiding
```java
class A {
    static String s() { return "A.s"; }
    String i() { return "A.i"; }
}
class B extends A {
    static String s() { return "B.s"; }
    @Override String i() { return "B.i"; }
}
A ref = new B();
System.out.println(ref.s() + " " + ref.i());
```

<details><summary>Solution</summary>

`A.s B.i`. The static method is resolved by the declared type `A` (hiding); the instance method by the actual type `B` (overriding).
</details>

## 2. Predict the output: constructor calling an overridable method
```java
class Base {
    Base() { System.out.println(describe()); }
    String describe() { return "base"; }
}
class Child extends Base {
    private String name = "child";
    @Override String describe() { return "I am " + name; }
}
new Child();
```

<details><summary>Solution</summary>

`I am null`. `Base()` runs before `Child`'s field initializer, but dynamic dispatch already calls `Child.describe()`, which sees `name` as null.

## 3. Design a parking lot (classes only)
Design classes for a parking lot with spots of sizes SMALL, MEDIUM, LARGE and vehicles Bike, Car, Truck. A vehicle fits in a spot of its size or larger. Write `park(Vehicle)` returning the spot or empty.

<details><summary>Solution</summary>

```java
import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

public class ParkingLot {
    enum Size { SMALL, MEDIUM, LARGE }

    sealed interface Vehicle permits Bike, Car, Truck { Size size(); }
    record Bike(String plate) implements Vehicle { public Size size() { return Size.SMALL; } }
    record Car(String plate) implements Vehicle { public Size size() { return Size.MEDIUM; } }
    record Truck(String plate) implements Vehicle { public Size size() { return Size.LARGE; } }

    static final class Spot {
        final int id; final Size size; private Vehicle parked;
        Spot(int id, Size size) { this.id = id; this.size = size; }
        boolean fits(Vehicle v) { return parked == null && size.compareTo(v.size()) >= 0; }
        void park(Vehicle v) { parked = v; }
        void leave() { parked = null; }
        @Override public String toString() { return "Spot" + id + "(" + size + ")"; }
    }

    private final List<Spot> spots = new ArrayList<>();

    ParkingLot(int small, int medium, int large) {
        int id = 1;
        for (int i = 0; i < small; i++) spots.add(new Spot(id++, Size.SMALL));
        for (int i = 0; i < medium; i++) spots.add(new Spot(id++, Size.MEDIUM));
        for (int i = 0; i < large; i++) spots.add(new Spot(id++, Size.LARGE));
    }

    Optional<Spot> park(Vehicle v) {
        for (Spot s : spots) {              // spots are ordered small to large: best fit first
            if (s.fits(v)) { s.park(v); return Optional.of(s); }
        }
        return Optional.empty();
    }

    public static void main(String[] args) {
        ParkingLot lot = new ParkingLot(1, 1, 1);
        System.out.println(lot.park(new Car("C1")));    // Optional[Spot2(MEDIUM)]
        System.out.println(lot.park(new Car("C2")));    // Optional[Spot3(LARGE)]
        System.out.println(lot.park(new Truck("T1")));  // Optional.empty
        System.out.println(lot.park(new Bike("B1")));   // Optional[Spot1(SMALL)]
    }
}
```
Talking points: enum ordering for size comparison, sealed vehicles, encapsulated spot state, `Optional` for "maybe no spot".
</details>

## 4. Fix the equals method
```java
class User {
    String email;
    public boolean equals(User other) { return email.equals(other.email); }
}
```
Find three problems and fix them.

<details><summary>Solution</summary>

1. The parameter is `User`, so it overloads instead of overriding `equals(Object)`: collections ignore it.
2. No `hashCode`, so hash collections break.
3. No null or type check; `email` may also be null.

```java
import java.util.Objects;

final class User {
    private final String email;
    User(String email) { this.email = email; }

    @Override public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User u)) return false;
        return Objects.equals(email, u.email);
    }
    @Override public int hashCode() { return Objects.hashCode(email); }
}
```
</details>

## 5. Interface vs abstract class choice
You need `Report` types (PDF, CSV, HTML). All share a title, a creation date and a `generate()` algorithm: header, body, footer. Only the body differs. Some reports must also be `Emailable`. Write the skeleton.

<details><summary>Solution</summary>

```java
import java.time.LocalDate;

public class Reports {
    interface Emailable { String toEmailBody(); }

    static abstract class Report {                       // shared state + algorithm
        protected final String title;
        protected final LocalDate created = LocalDate.of(2026, 1, 1);
        protected Report(String title) { this.title = title; }

        public final String generate() {                 // template method
            return header() + body() + footer();
        }
        private String header() { return "== " + title + " ==\n"; }
        private String footer() { return "\n-- " + created + " --"; }
        protected abstract String body();
    }

    static class CsvReport extends Report implements Emailable {
        CsvReport(String t) { super(t); }
        protected String body() { return "id,total\n1,50"; }
        public String toEmailBody() { return "Attached CSV: " + title; }
    }

    static class HtmlReport extends Report {
        HtmlReport(String t) { super(t); }
        protected String body() { return "<table><tr><td>50</td></tr></table>"; }
    }

    public static void main(String[] args) {
        System.out.println(new CsvReport("Sales").generate());
        System.out.println(new CsvReport("Sales").toEmailBody());
    }
}
```
Abstract class for shared state and the fixed algorithm; interface for the optional capability.
</details>

## 6. Count instances safely
Write a class that counts how many instances were created, and a static method to read the count. What breaks with many threads?

<details><summary>Solution</summary>

```java
import java.util.concurrent.atomic.AtomicInteger;

class Widget {
    private static final AtomicInteger CREATED = new AtomicInteger();
    Widget() { CREATED.incrementAndGet(); }
    static int created() { return CREATED.get(); }
}
```
A plain `static int count; count++;` loses updates when threads run it at the same time, because `++` is read, add, write (three steps). `AtomicInteger` makes it atomic (Phase 9).
</details>

## 7. Immutable value object
Create an immutable `Email` value object that validates format, normalizes to lower case, and can be used as a map key.

<details><summary>Solution</summary>

```java
import java.util.Locale;

record Email(String value) {
    Email {
        if (value == null || !value.matches("^[^@\\s]+@[^@\\s]+\\.[^@\\s]+$"))
            throw new IllegalArgumentException("invalid email: " + value);
        value = value.toLowerCase(Locale.ROOT);
    }
}
// new Email("Ann@Shop.com").equals(new Email("ann@shop.com"))  -> true
```
A record gives equals, hashCode and toString; the compact constructor validates and normalizes.
</details>

## 9. Replace a type switch with polymorphism
Refactor:
```java
double fee(String type, double amount) {
    if (type.equals("CARD")) return amount * 0.03;
    if (type.equals("BANK")) return 1.0;
    if (type.equals("WALLET")) return amount * 0.01;
    throw new IllegalArgumentException();
}
```

<details><summary>Solution</summary>

```java
enum PaymentType {
    CARD   { double fee(double amount) { return amount * 0.03; } },
    BANK   { double fee(double amount) { return 1.0; } },
    WALLET { double fee(double amount) { return amount * 0.01; } };

    abstract double fee(double amount);
}
// PaymentType.valueOf("CARD").fee(100)  -> 3.0
```
Each constant owns its rule; adding a new type forces you to implement `fee`, and strings like "crad" are rejected at the boundary by `valueOf`.
</details>

## 10. Composition over inheritance
A teammate wrote `class AuditedList extends ArrayList<String>` that logs every `add`. Explain the risk and rewrite it.

<details><summary>Solution</summary>

Risk: `ArrayList.addAll` does not call `add` (it copies arrays), so bulk adds are not logged; other inherited methods (`set`, `add(index, e)`, `removeIf`) bypass the log too. Depending on internals is fragile.

```java
import java.util.ArrayList;
import java.util.Collection;
import java.util.List;

final class AuditedList {
    private final List<String> inner = new ArrayList<>();
    void add(String s) { System.out.println("add " + s); inner.add(s); }
    void addAll(Collection<String> c) { c.forEach(this::add); }
    List<String> snapshot() { return List.copyOf(inner); }
}
```
Only the operations you expose exist, and each one is logged.
</details>

| Not polymorphic | Fields and static methods |
| Abstract class vs interface | State and constructors vs contract and multiple inheritance |
| Default methods | Evolve interfaces; class wins; diamond needs override |
| final | Variable once, method not overridable, class not extendable; reference not object |

## The 10 most likely interview questions

1. **Four pillars of OOP?** Encapsulation, inheritance, polymorphism, abstraction, each with an example.
2. **Abstract class vs interface?** State and constructors and single inheritance vs contracts and multiple inheritance; choose by "shared state" vs "capability".
3. **Overloading vs overriding?** Different parameters at compile time vs same signature at runtime.
4. **Can you override static or private methods?** No: static is hidden, private is invisible.
5. **equals and hashCode contract?** Equal objects must have equal hash codes; override both.
6. **What breaks if only equals is overridden?** HashMap lookups and HashSet de-duplication.
7. **How to make a class immutable?** The five-step recipe.
8. **Composition vs inheritance?** HAS-A vs IS-A; favour composition.
9. **What is a record and where do you use it?** Immutable data carrier; DTOs, projections, keys; not entities.
10. **Why compare enums with `==`?** One instance per constant; null-safe.

## Rapid-fire flashcards

Q: What does `super()` call if a constructor does not call it explicitly?
A: The parent's no-arg constructor, inserted by the compiler.

Q: Which access level allows subclasses in other packages but not unrelated classes?
A: `protected`.

Q: Which method resolution happens at compile time: overloading or overriding?
A: Overloading.

Q: Can an interface have a constructor?
A: No.

Q: What is the default `toString` format of `Object`?
A: `ClassName@hexHashCode`.

Q: Why is `Stack extends Vector` considered bad design?
A: Stack inherits list operations that break stack behaviour; composition would hide them.

Q: What hidden reference does a non-static inner class keep?
A: A reference to the enclosing outer instance.

Q: What method lists all constants of an enum?
A: `values()`.

Q: What is a compact constructor in a record?
A: A canonical constructor without a parameter list, for validation and normalization.

Q: Does `final List<String> list` make the list unmodifiable?
A: No; only the reference is fixed.
